# Docker Agent 容器绑定修复

## 需求与兼容边界

- 新建 Agent 默认按容器名称绑定，容器重建后可继续跟随同名容器。
- 已有 Agent 的显式绑定方式保持不变；旧 JSON 缺少绑定字段时仍按 ID 解释，不静默迁移或改选其他容器。
- 名称与 ID 都通过远端 Docker 查询容器用户；查询失败保留真实错误与手动用户输入，不伪造用户列表。

## 已确认机制与修复范围

- 表单与模型原先默认 `id`；模型新建默认改为 `name`，旧 JSON 回读保留 `id`。
- 表单切换绑定时未匹配当前引用会退回第一个容器，可能查错目标。应仅转换精确名称、完整 ID 或唯一匹配的短 ID；无匹配不自动选择，空引用保持为空。
- 清空引用或切换执行位置时旧异步用户查询未立即失效，可能回写旧用户/错误。目标变化立即失效旧请求，取消等待中的查询；每次查询仅回写其对应当前目标。
- `listContainerUsers` 已把引用安全引用后传给 `docker exec -i <reference> cat /etc/passwd`，无 ID 专属分支。尚无用户提供的原始 ID 错误，不能据此宣称远端问题已复现。
