# Flutter 远程服务器与 AI Agent 管理面板

## 1. 项目概述

### 1.1 项目定位

本项目是一款基于 **Flutter** 开发的跨平台服务器管理客户端。

核心定位不是单纯的 SSH 客户端，而是：

> **AI Agent + SSH + 文件管理 + 终端 + Docker + 快捷命令 + 服务器管理的一体化客户端。**

用户通过一个 Flutter App 连接远程 Linux 服务器，在同一个应用中完成：

* SSH 服务器管理
* AI Agent 管理
* Claude Code 控制
* Codex 控制
* OpenCode 等 ACP Agent 控制
* Agent Session 管理
* AI 对话
* AI Tool Call 查看
* AI 权限审批
* 服务器文件管理
* 文件上传/下载
* 文件编辑
* SSH 终端
* 进程管理
* Docker 管理
* Docker Compose 管理
* 容器日志
* 容器终端
* 快捷命令
* 服务器资源监控
* 系统服务管理
* 系统信息查看

项目最终形成：

# 2. 设计原则

## 2.1 不自定义底层协议

项目禁止自行设计类似：

```text
/api/server
/api/docker
/api/agent
/ws/terminal
/ws/agent
```

这样的私有协议。

所有通信尽量使用已经存在的标准：

| 场景        | 协议                             |
| --------- | ------------------------------ |
| 服务器连接     | SSH                            |
| 文件传输      | SFTP                           |
| AI Agent  | ACP                            |
| ACP 消息    | JSON-RPC                       |
| ACP 远程传输  | WebSocket / SSH                |
| Docker    | Docker CLI / Docker Engine API |
| 本地数据库     | SQLite                         |
| WebSocket | WebSocket                      |
| Markdown  | Markdown / CommonMark / GFM    |
| 代码高亮      | TextMate / Highlight.js        |
| 终端        | xterm                          |
| 路由        | Flutter Router / go_router     |

ACP 官方定位就是用于 Client/IDE 与 Coding Agent 的标准通信，并支持本地 stdio 和远程场景。

# 38. Agent Session 持久化

需要区分：

```text
SSH Connection
```

和：

```text
Agent Session
```

不能让 Agent 生命周期完全绑定 App UI。

目标：

```text
App
 ↓
SSH
 ↓
ACP Agent
 ↓
Session
```

App 断开：

```text
App ❌
SSH ❌
Session仍存在
```

重新打开：

```text
App
 ↓
SSH
 ↓
ACP
 ↓
session/list
 ↓
session/resume
```

ACP 的 `session/resume` 已经稳定，用于重新连接已有 Session。

### 持久化与断线处理细节：

1. **会话状态（Context & History）持久化**：
   * Agent（如 Claude Code / Codex）在服务器端具有本机会话存储（如 `~/.claude/sessions`）。
   * 当 SSH 断开重连时，客户端重新拉起 ACP Adapter，调用 `session/list` 可获取历史会话，调用 `session/resume` 恢复上下文与历史，不依赖单次长连接内存。
2. **长时活跃任务与断线信号（SIGHUP）**：
   * 默认模式下，SSH 管道断开会向当前执行进程传递 `SIGHUP`，当前正在流式生成的单次请求会被打断，但此前已提交的会话历史安全保留。
   * 对于需要保持后台长时构建/执行的场景，后续阶段可扩展通过 `tmux` / `nohup` / `systemd --user` 等轻量守护方式托管 ACP 进程，或在断线重连时重放未完成状态。

### 51.1 采集性能与资源保护策略

为避免频繁建立 SSH Exec 通道引发服务器进程高频 fork/exec 消耗 CPU，以及手机端耗电和流量浪费，采取以下优化：

1. **生命周期自适应感知**：
   * 仅在用户位于 Dashboard / System 页面时激活采集；
   * 切换至其他页面或 App 退至后台时，**立即暂停轮询与数据流**。
2. **轻量流式监听 vs 节流轮询**：
   * 优先方案：保持单个轻量级 SSH Channel，通过简单命令流（如 `vmstat 3` 或聚合采集小脚本）持续流式吐出度量数据；
   * 备选方案：定时轮询间隔设置为 3~5 秒，批量单次执行获取聚合指标，禁止每秒高频并发建立多个 SSH 连接。

### 75.1 SSH 环境变量与 PATH 探测机制

在非交互式 SSH 会话中，默认不加载用户个人环境配置文件（如 `~/.bashrc`、`~/.zshrc`），导致通过 `nvm`、`fnm`、`pnpm`、`cargo` 安装在用户主目录下的 Agent CLI（如 `claude`、`codex`）无法被常规 `which` 命中。

客户端探测与拉起 Agent 时采用如下策略：

1. **登录 Shell 执行器（Login Shell Wrapper）**：
   * 探测与执行统一包装为：`bash -l -c "<command>"`，确保完整加载 `~/.profile` 与环境变量；
2. **多路径回退探测**：
   * 预设探测常见安装路径：
     * `~/.local/bin`
     * `~/.nvm/versions/node/$(ls ~/.nvm/versions/node 2>/dev/null | tail -n 1)/bin`
     * `~/.fnm/current/bin`
     * `~/.cargo/bin`
     * `/usr/local/bin`
3. **用户自定义路径配置**：
   * 在 Agent 设置中允许用户指定自定义可执行文件绝对路径或补充环境变量。

# 77. 权限模型

应用本身不应该默认获得：

```text
root
```

服务器连接使用普通用户。

需要管理 Docker：

```text
docker group
```

或者：

```text
sudo
```

需要系统管理权限时才使用 sudo。

Docker 官方也说明默认 Docker Unix socket 通常由 root 拥有，非 root 用户需要 docker group 或 sudo 才能访问。

### 77.1 Sudo 交互与 TTY 缺失处理

非交互式 SSH Exec 在执行 `sudo` 时若需密码，会导致 `sudo: a terminal is required to read the password` 错误。应用采取以下三重机制：

1. **优先推荐规范配置**：
   * 引导用户将登录账号加入 `docker` 用户组；
   * 或在 `/etc/sudoers.d/` 中为特定安全命令配置免密（`NOPASSWD`）。
2. **sudo -S 管道输入支持**：
   * 当命令标记需要提权且需要密码时，执行模式采用 `sudo -S`，由客户端从 `flutter_secure_storage` 安全读取用户密码并通过 stdin 管道写入，避免无 TTY 报错。
3. **PTY 弹窗提权交互**：
   * 对于未知或偶发的提权命令，自动升轨为轻量 PTY 交互流，提示用户输入 sudo 密码并回传。

# 119. 最终设计决策

```text
Flutter
    ↓

    ↓

    ↓

    ↓
Remote Linux Server
```

```text

不自定义 Agent 协议
不实现 SSH
不实现 SFTP
不实现 ACP
不实现 JSON-RPC
不实现 WebSocket
不实现 Terminal
不实现 Markdown
不实现 Syntax Highlight
不实现 SQLite
不直接暴露 Docker TCP
```

所有底层能力优先使用成熟现成实现。

业务代码只负责：

```text
连接
管理
组合
展示
缓存
交互
```

最终形成一个真正的：

> **Flutter 原生跨平台 AI-Native Server Management Client。**
