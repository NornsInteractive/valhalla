# Valhalla - 产品需求规格说明书 (PRD)

## 2026-10-23 ACP 持续运行与每日更新（已实现）

- 用户确认后，在所连服务器部署用户级后台代理；宿主机与 Docker Agent
  均通过原 SSH 身份执行，不新增公网服务或替换 Agent 登录。
- 手机退到后台、锁屏或进程退出后，已受理任务继续执行；返回时先保留
  本地记录，再按游标补传，接续同一任务。不得以重发问题模拟恢复。
- 审批在断线期间继续等待。只有用户明确停止或审批决定才改变远端任务。
- 已完成输出保存七天。服务器重启、容器/Agent 终止和存储故障须如实
  显示，不能宣称任务仍运行；恢复异常提示允许关闭并保留诊断。
- 每日首次前台进入按本地日历检查更新；仅有新版本才弹窗，同日一次，
  输入法或其他弹窗期间延后。用户手动检查不受每日频率限制。
- 门禁含模拟协议/持久化回归及 Android 强制关闭后补传；测试结果与
  尚未完成的设备/平台范围分开记录，不把逻辑测试当作已安装验证。

1.0.16+17 已发布，已验证与未覆盖范围见[发布回执](../../agent-workflow/2026-10-23-v1016-release.md)。

## 2026-10-15 核心体验优先（已批准，验收中）

本轮不扩展NAS或应用中心功能，完成六项高频体验：传输暂停原因及批量控制、
多对象恢复入口、ACP流式局部更新和准确错误动作、文件工具栏收敛、终端历史
分组搜索、设置搜索与应用安装身份。沿用现有能力，不增加依赖或自动远端操作。

手动暂停不得自动继续，重启恢复的传输须显式继续；批量恢复只作用于当前服务器
调用时的暂停任务。重连保留缓存，禁止自动发送消息、审批或终端输入。自动新终端
仍是普通SSH，手动新建才按tmux开关，默认历史精确恢复规则不变。配置迁移不包含
密码或私钥，不读取旧包私有数据；关于及诊断显示应用本身的平台和架构。

交付为本地同版本Android包与保留数据ADB验收，不推送或发布。设备实测、隔离VM、
模拟ACP与单元测试分别报告；没有独立ACP目标时不得宣称真实对话已验。
详细契约与证据见[本轮台账](../../agent-workflow/2026-10-15-core-experience.md)。

## 实验性应用中心（2026-10-12 实施中）

## 核心稳定性与高频操作优化

同进程恢复保持页面、草稿和滚动，重新启动恢复既有持久化状态且标明缓存；
不得自动重发聊天、审批或运维动作。ACP 阅读历史时不被新输出抢走位置，
旧会话的延迟滚动回调不能作用于新会话。远程文件同目录刷新和页面返回保持
浏览位置，新目录与不同服务器不串用滚动状态；万条目录的过滤排序不因
传输进度重复执行。更新打开合并重复点击，校验期间包变更或页面状态失效
不能继续执行旧打开操作。诊断只记录类别、时长、固定结果与数量，仍可本地
导出，不自动上传用户内容。本轮 NAS 离线能力另期实施，设备实测与模拟
测试必须分别报告。实现及验收以
[本轮台账](../../agent-workflow/2026-10-11-core-stability.md)为准。

## 2026-10-11 文件显示与安全操作、系统与更新（本轮实施中）

开启显示隐藏文件时，隐藏项图标与文件名略淡，仍需可读、可选、可操作；
不能把它们伪装为禁用项，`..` 导航不弱化。列表／卡片视图可显式切换，
跨重启保留，失败不谎报已保存；切换不改变筛选、排序或符号链接行为。

文件编辑保存前必须检测原文和目标身份冲突，不得覆盖其他程序的新内容；
冲突可复制草稿／明确重新读取，退出提供保存、保留草稿和放弃选项。
上传不得截断同名文件，下载和上传重启后保持记录且只能显式续传；源改变
或 partial 无法验证时停止，完成下载打开前再验证本地内容。发布中的任务
不能虚假显示已取消，清理失败记录不能被静默删除。

系统服务要显示真实开机状态、明确的权限／不支持／查询错误和有界日志；
运行中操作必须可识别，不能自动重试重启／停止／结束进程等动作。
NAS 缓存清理只删除缩略图，不触及索引和远端文件；取消不可见缩略图工作，
显式播放恢复保留位置和队列。实验性功能默认关闭不变。

关于界面保留 GitHub 开源仓库入口；更新检查和下载统一通过
`https://ygg.norns.cc.cd` 公开客户端 API，复用 `com.norns.valhalla` 平台目录，
按平台／架构匹配正式包，不回退 GitHub 更新发现或把管理令牌嵌入应用。
按应用运行 ABI 获取架构，检查与下载显式携带平台／架构，下载按 package_id
绑定并校验每包 SHA-256；不按设备支持的 ABI 列表替换应用原架构。
服务器回退到其他平台包时也不得安装。目录完整版本名和原生 ABI 版本码
分别处理，同一 `1.0.4+5` 不应因共享目录版本码而一直提示更新。
默认每日检查可关闭，手动检查不依赖 SSH。下载／安装必须明确确认，
显示进度、暂停／续传与失败原因，验证平台、大小、哈希及 Android 包和
证书后才能请求系统安装，不通过卸载解决证书冲突。不声称 iOS 可安装
未签名包或 Linux 环境已完成 Windows 原生验证。

不保证系统杀进程后远端任务继续执行；无可靠回放能力时提示部分输出无法恢复。
实现和实际验证记录见[本轮交接](../handoffs/2026-09-30-background-session-recovery.md)。

## 1. 产品背景与定位

### 1.1 业务痛点
当前开发者和运维工程师在远程管理 Linux 服务器与使用 Coding AI Agent 时面临严重的工具割裂：
1. **工具多端切换**：需要同时打开 SSH 终端客户端（如 Termius/PuTTY）、Docker 面板（如 Portainer）、SFTP 工具（如 FileZilla）以及各自独立的 AI 聊天或 CLI 工具。
2. **移动端缺乏现代化 Agent 体验**：Claude Code、Codex 等新一代 Coding Agent 深度集成于终端 CLI 或桌面 IDE，在移动端（手机/平板）几乎没有开箱即用的优质会话与权限控制客户端。
3. **私有协议维护沉重**：大多数传统运维面板强制在服务器端安装私有 Agent 后端，暴露出端口暴露高危、私有 API 升级破坏性大等问题。

### 1.2 产品定位
**Valhalla** 是一款基于 **Flutter** 开发的原生跨平台 **AI-Native 远程服务器与 AI Agent 一体化管理客户端**。

> **核心定位**：以标准 ACP 协议与 SSH 协议为基石，将 AI Agent 深度结合终端、文件、Docker 与系统运维能力，提供无缝的跨平台（Android、Windows、iOS、macOS、Linux）全功能运维体验。

## 3. 功能需求规格 (Functional Requirements)

### F1: 服务器连接与配置管理 (Server & SSH)
* **F1.1 服务器 Profile CRUD**：
  * 支持配置：名称、分组/标签、主机地址（支持 IPv4、IPv6、域名、Tailscale/WireGuard 虚拟内网 IP）、SSH 端口（默认 22）、登录用户名。
  * 认证方式支持：私钥（带 Passphrase 支持）、密码、Keyboard-Interactive。
* **F1.2 敏感凭证安全存储**：
  * 私钥、Passphrase 和登录密码严禁明文存入 SQLite，必须通过平台安全密钥库（Android Keystore / Windows Credential Manager / iOS Keychain）隔离存储。
* **F1.3 Host Key 验签与防 MITM**：
  * 首次连接校验指纹（SHA256），提示用户确认；
  * 保存已知指纹到本地数据库（Known Hosts），后续连接若指纹变更强制阻断并告警。
* **F1.4 连接保活与重连机制**：
  * 支持 SSH KeepAlive 心跳包；
  * 检测网络中断后提供一键重连与断线提示。

### F2: AI Agent & ACP 会话系统 (Core Agent System)
* **F2.1 零服务端改造标准对接**：
  * 严格基于 ACP (Agent Client Protocol) 标准规范对接服务端 Agent（Claude Code、Codex、OpenCode 等），通过 SSH 通道传输 JSON-RPC。
* **F2.2 Agent 环境检测与状态展示**：
  * 自动通过 Login Shell 探测服务器已安装的 Agent 类型、版本、运行状态与路径。
* **F2.3 Session 全生命周期管理**：
  * 创建会话（可指定工作目录 `cwd`、Model、Mode、Reasoning Level 等配置项）；
  * 会话列表展示、多会话切换、历史会话加载（`session/list`, `session/resume`, `session/close`）；
  * 实时标题与元数据同步（响应 `session_info_update`）。
* **F2.4 流式消息与富文本渲染**：
  * 实时展示用户输入、Agent 文本、Thinking（思考折叠块）、Plan（执行计划）；
  * 完整的 GFM Markdown 语法解析（表格、代码块语法高亮、任务列表）。
* **F2.5 Tool Call 交互式卡片**：
  * 可视化展示工具调用状态（Pending、Running、Completed、Failed、Cancelled）；
  * 折叠展示工具输入参数与输出结果。
* **F2.6 标准权限审批（Permission Approval）**：
  * 拦截 Agent 提出的高危命令/写文件等敏感行为；
  * 提供【拒绝】、【允许一次】、【始终允许】三态审批弹窗。

### F3: SFTP 文件管理 (File Management)
* **F3.1 文件目录树与列表浏览**：
  * 支持路径跳转（`/`、Home、自定义路径、最近访问、收藏夹）；
  * 展示文件图标、名称、大小、修改时间、Linux 权限位（如 `drwxr-xr-x`）。
* **F3.2 基础文件操作**：
  * 新建文件/文件夹、重命名、删除、移动、复制、权限查看/修改。
  * 支持列表项多选与批量删除/下载。
* **F3.3 文件上传与下载**：
  * 移动端与桌面端原生文件选择器（`file_picker`）；
  * 上传/下载进度条、传输速率展示及取消操作。
* **F3.4 内置代码与文本编辑器**：
  * 支持常用文本/配置文件编辑（yaml, json, sh, py, conf, env, md 等）；
  * 集成 TextMate 语法高亮、行号显示、保存快捷键（Ctrl+S / Command+S）。

### F4: SSH 终端仿真器 (Terminal)
* **F4.1 终端核心体验**：
  * 基于 `xterm.dart` 渲染，支持 60fps 高帧率输出、CJK 双宽字符、Unicode 及 Emoji；
  * 支持 ANSI 256 色及 TrueColor 真彩色主题。
* **F4.2 多终端会话与 Tab 管理**：
  * 支持打开多个独立 Shell 终端，支持自由切换、重命名 Tab、关闭会话。
* **F4.3 移动端辅助键栏 (Accessory Keyboard Bar)**：
  * 针对移动端软键盘缺少功能键的场景，提供浮动快捷条，集成：`Ctrl`, `Alt`, `Esc`, `Tab`, `↑`, `↓`, `←`, `→` 及剪贴板粘贴。
* **F4.4 中文及多语言 IME 输入法兼容**：
  * 解决移动端中文输入法合成词与终端直接字符流之间的冲突与错位。

### F5: Docker & 容器化编排 (Docker Management)
* **F5.1 容器生命周期管理**：
  * 容器列表查看（状态：Running, Stopped, Paused, Restarting）；
  * 快捷控制：启动、停止、重启、暂停、恢复、删除、重命名。
* **F5.2 容器深度感知**：
  * 实时日志流（`docker logs -f`，支持自动滚屏、暂停、关键字搜索）；
  * 容器终端交互（基于 `docker exec -it` 直通 `xterm`）；
  * 容器 Inspect 详细元数据（端口映射、挂载卷、环境变量、网络拓扑）。
* **F5.3 Docker 资源概览 (Phase 2)**：
  * 镜像（Images）列表、Pull、删除、构建历史；
  * 卷（Volumes）与网络（Networks）列表与清理。
* **F5.4 Docker Compose 支持 (Phase 2)**：
  * 项目拓扑展示、Compose Up / Down / Restart、配置查看。

### F6: 系统进程与服务管理 (Process & Service)
* **F6.1 进程管理器**：
  * 基于标准 `ps` 呈现进程列表，支持按 CPU、Memory 降序排序与关键字模糊搜索；
  * 支持向进程发送终止信号（`kill -15` SIGTERM, `kill -9` SIGKILL）。
* **F6.2 Systemd 服务管理器**：
  * 展示系统核心服务（`systemctl`）状态（Running, Inactive, Failed）；
  * 提供服务 Start, Stop, Restart, Reload, Enable, Disable 控制，并查看服务日志（`journalctl`）。

### F7: 快捷命令与自动化 (Quick Commands)
* **F7.1 命令库管理**：
  * 分类管理常用命令（Docker 维护、系统清理、服务重启等）；
  * 支持全局通用命令与绑定特定服务器的专用命令。
* **F7.2 动态参数模版注入**：
  * 支持 `{{variable}}` 占位符（如 `systemctl restart {{service_name}}`），执行前弹出简洁参数输入表单。
* **F7.3 危险指令安全熔断**：
  * 识别高危命令模式（如 `rm -rf`, `prune -a`, `reboot`），强制触发红色二级确认弹窗。

### F8: 系统状态概览 (Dashboard & Metrics)
* **F8.1 核心硬件指标展示**：
  * CPU 使用率、物理内存占用（已用/总量）、根目录/数据盘使用百分比、系统负载（Load 1/5/15）、持续开机时间（Uptime）。
* **F8.2 资源消耗保护策略**：
  * 自适应流式监听，仅在处于 Dashboard 前台页面时采集，退至后台或切页立即阻断，严禁高频 fork 进程损耗服务器资源。

### F9: 跨模块 Agent 协同 (Cross-Module AI Collaboration)
* **F9.1 文件上下文传导**：文件右键 -> “Ask Agent” -> 自动引入文件路径与内容至 ACP 会话。
* **F9.2 终端报错联动**：终端选中异常报错日志 -> “Ask Agent” -> 携带错误上下文发起排查。
* **F9.3 容器与系统故障联动**：容器故障退出状态或 Dashboard CPU 报警卡片 -> 一键携带诊断上下文呼出 Agent。

### F10: NAS 媒体库 (Remote Media Library)
* **F10.1 扫描范围配置**：每台服务器独立配置一个或多个绝对扫描目录及排除目录；排除优先，不跟随符号链接。
* **F10.2 只读远端扫描**：通过后台 SSH `find` 扫描图片、视频和音乐，不部署远端服务、不写远端索引、不进入交互终端历史。
* **F10.3 本地媒体索引**：扫描成功后按服务器原子替换本地 SQLite 索引；扫描失败或取消必须保留上一次完整结果。
* **F10.4 浏览与打开**：支持名称搜索和媒体分类；图片按需缓存缩略源文件，视频和音乐进入既有下载队列，完成后由系统应用打开。

### F11: 会话运行设置
* **F11.1 会话级配置**：ACP 与支持结构化协议的 CLI 会话可选择模型、推理等级及操作权限；每次修改同时成为当前服务器与 Agent 的新会话默认值。
* **F11.2 能力驱动**：模型和推理选项只使用 Agent/协议实际声明的能力；不支持结构化配置的交互 CLI 由 CLI 自身管理。
* **F11.3 权限策略**：默认每次询问；安全自动允许仅放行明确只读请求；全部自动允许必须二次确认，协议无法表达允许结果时保持拒绝。

用户确认数据保留范围为进程存活期间的切后台和锁屏，不新增整套冷启动页面快照持久化。恢复连接不得清空已展示数据、草稿、选择及滚动状态；新结果成功才局部更新。自动检测必须覆盖连接先于 Agent 管理创建的时序，不能要求手动刷新。
