# ACP 智能会话工作台

## 使用目标

重新进入应用时先显示本地已存会话和最后一页消息，再恢复远端状态。联网、检测、恢复中不替换消息列表。首次进入定位最新消息；用户上滑之后保持阅读位置。导航和草稿编辑不会创建远端会话。

项目为自动分组而非另一套会话系统：服务器、会话创建时的执行环境、规范化工作目录组成分组键。支持别名和收藏，保持现有默认 Agent/会话偏好。已有会话缺少执行快照时保留旧环境标记，不推测原容器；后续新会话和每个参与 Agent 的远端上下文均持久化执行快照。修改 Agent 执行环境后原快照不随之改变，同 Agent 的旧会话仍可阅读，但不能静默在新环境继续运行或读写文件。

## 展示与交互契约

- 手机：复用左侧项目/会话抽屉；文件与任务按需面板；输入框周围保留模型、推理、权限与上下文入口。
- 桌面：相同数据和组件，项目侧栏、会话主体、可折叠文件/任务详情。无第二个独立聊天页面。
- 文件：当前执行环境内浏览、引用、预览；可编辑文本先展示差异再明确确认保存。目标变化或文件外部修改拒绝覆盖且保留用户编辑内容。二进制或大文件不进入文本编辑。
- 链接：普通 HTTP/HTTPS/mailto 使用系统应用；Markdown 默认语法已支持普通网址自动识别，点击绑定单独处理，不复用 OAuth 认证流程。远端文件链接按工作目录解析，目录外引用需确认，不当作手机本地路径。
- 网页预览：仅用户确认后转发远端 HTTP localhost；设备仅 loopback 监听；Docker 仅使用已有发布端口。无映射时解释原因，不修改 Docker 网络、不绕过 TLS。
- 任务：复用既有流式事件、审批、计划、工具输出分页与诊断，显示实际提供的能力。每台服务器一个执行任务；其它会话可查看和编辑草稿，不自动排队或重发有副作用的请求。

## 核心实现

本地消息读取拥有独立于传输请求的读取版本。远端断线、适配器生命周期变更不会使仍属于当前会话的 SQLite 读取作废；目标/选择与读取版本共同隔离迟到结果。运行中输出与读取结果按消息 ID 合并，实时版本优先。

文件编辑上限沿用 SFTP 的 1 MiB，严格 UTF-8。宿主机复用现有快照、哈希校验和 POSIX 原子重命名；容器以其配置用户执行 Python3，内容走 stdin，不进入命令参数。保存检查原路径、符号链接目标、内容摘要和元数据；同目录临时文件写入后再次校验并原子替换，保留权限。Python3 不可用时可回退有界只读预览，不安装工具、不提权。

SSH 历史初始状态为空、未知、不可用时先刷新来源。恢复校验 server/target/socket/session 身份；检测、查询与附加错误保留脱敏详情，不因同名复用已结束会话。附加失败保留原页签及诊断以重试同一身份，不分配替代 Shell 或重复历史页签。不修改服务端原会话。

## 验收与已知边界

测试范围：SQLite 冷启动、延迟 Agent 就绪、生成期间本地历史、目标切换与阅读位置；链接与分组；真实容器编辑脚本的隔离临时文件读写/冲突/符号链接；模拟 SSH 与隔离 tmux；NAS 转发兼容。

保存的最终校验与原子重命名之间仍可能被不配合的外部写入者抢占；完全消除此窗口需要服务器端协作锁。现有 SSH 正式包私有诊断文件不能通过普通 ADB 读取，真实恢复失败根因不得由源码推断代替。实际验证结果以本轮交付回执为准。
