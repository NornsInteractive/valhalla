# 服务器工作区与多设备配置

## 归属与启用

工作区属于服务器上的 SSH 用户。同一用户通过手机、平板或桌面端连接同一服务器，可复用 Agent 配置、智能会话、终端历史索引、文件偏好、应用中心与 NAS 数据。不同服务器或不同 SSH 用户各自保存；没有额外的 Valhalla 云账号。

新设备仍需添加 SSH 连接并确认主机密钥。连接后在设置中的“服务器工作区”发现现有工作区，预览本地待迁移内容并启用。发现操作不创建远端目录；启用后安装 Python 标准库组件。服务器需要 Python 3.9 或以上，不要求 sudo，不监听公网端口。

停止同步保留远端数据与本机数据。清除同步缓存不删除 SSH 配置；存在未提交修改时拒绝清除，先同步或解决冲突。不要通过删除整个应用数据来处理同步失败。

## 保存范围

| 范围 | 服务端保存 | 本机保留 |
| --- | --- | --- |
| Agent | 执行位置、容器名称/用户、CLI/ACP 命令与默认选择 | 设备相关检测缓存 |
| 智能会话 | 会话索引、消息角色、工具调用、运行索引与附件引用 | 当前显示窗口、附件按需缓存 |
| SSH 终端 | tmux 历史名称、默认恢复项、隐藏项与索引 | 普通 SSH 进程、活跃页签、渲染缓冲 |
| 远程文件 | 书签、最近目录与界面偏好 | 下载/上传队列、下载文件 |
| 应用中心 | 应用源、已部署实例元数据 | 安装表单中的机密、设备侧任务状态 |
| NAS | 媒体源元数据、扫描规则、索引、收藏与播放进度 | 密码/令牌、缩略图、离线媒体 |
| 界面偏好 | 手机/平板/桌面各自的偏好配置 | 窗口尺寸、键盘和即时交互状态 |
| 草稿 | 按设备区分的对话与文件编辑草稿 | 当前编辑内容和恢复前备份 |

SSH 密码、私钥、主机信任、sudo 密码及 NAS 认证凭据不参加同步。Agent 的登录凭据继续属于远端运行用户或容器用户。手动放在命令、消息或附件中的敏感内容属于业务正文，不会通过字符串猜测自动删除；启用前确认该 SSH 用户下的数据允许在自己的设备间共享。

## 应用偏好与服务器切换

应用级偏好只有一个指定来源，首次启用的服务器默认成为来源。连接其他服务器不会改变主题、语言或底部导航。可在工作区设置中明确切换来源。手机、平板、桌面的界面偏好分别记录，避免窄屏布局覆盖桌面布局。

业务记录保留原有稳定 ID，服务器的本机连接 ID 在传输时映射为工作区作用域，不全局替换路径或消息文本。旧本机缓存仍然可用，断线时先显示缓存，重连后合并更新，不清空界面。

## 同时查看与操作 ACP

多个设备可同时查看同一会话，但只有取得控制权的设备能发送消息、审批、取消或修改运行设置。另一个设备可明确确认接管，旧设备之后的修改请求会被服务器拒绝。

控制租约持续 60 秒，前台设备每 20 秒续期。退出应用或后台暂停续期后，租约可过期；这不会取消正在运行的 Agent。输出继续由服务器记录。返回时按已有运行键与输出序号接续，不依靠原设备的内存状态。没有运行的只读会话不会自动启动新 Agent。

旧持久化运行不被自动终止或替换。旧协议运行需要升级时先显示明确状态；有任务正在执行时保留它，不能为了启用同步强制重启。

## 冲突与草稿

每条记录使用版本比较与幂等操作 ID，断线重试不会重复提交。两个设备修改同一版本时保留两份并显示冲突，由用户选择本地或服务器版本，不按设备时间盲目覆盖。

草稿按设备保存。其他设备草稿只在明确选择恢复后使用，不能自动覆盖当前输入。文件编辑草稿只恢复到编辑器，不直接覆盖服务器文件；保存文件仍执行原有的远端内容修订校验。

## 存储与维护

工作区目录是 SSH 用户的 `~/.local/share/valhalla/workspace-v1/`，包含 Python 组件、SQLite 数据库、附件和分块暂存。目录权限 0700、文件 0600，拒绝符号链接与非属主文件。请求通过 SSH 标准输入传输，不在进程参数中放业务正文或认证凭据。

服务器备份应在停止写入或使用 SQLite 备份 API 时获得一致快照；WAL 模式下不要只复制主数据库而遗漏未合并事务。恢复备份时保留工作区身份；身份变化会提示确认，避免把另一工作区误当原工作区同步。新版本遇到更高的存储协议版本必须拒绝写入，不能降级覆盖。

消息、媒体索引与附件分别按页/按需获取。启动同步仅拉取配置、偏好和草稿元数据，不下载全部对话、媒体原文件或缩略图。具体实现和验收状态记录在 `agent-workflow/2026-10-27-server-workspace.md`；本说明不代替实际测试报告。

NAS 认证与媒体源地址分别保存在不同的本机存储中。更新认证过程中若发生存储失败或退出，认证绑定会保持“未完成”状态，阻止把密码发往错误地址；重新输入并保存该媒体源的认证即可恢复。远端同步修改源地址时也需要在新设备明确配置对应认证，不会自动复用旧地址的密码。
