# Valhalla v1.0.3 release contract

User requests version 1.0.3 and GitHub Release publication. Latest clarification
excludes macOS AND Windows builds. Build Android and Linux locally; do not trigger
GitHub Actions. iOS also requires a Mac/Xcode unavailable in this Linux container;
do not claim an iOS package or relabel earlier assets. No web target exists.

## Source and ownership

- Version: 1.0.3+4; application IDs and fixed Android release key unchanged.
- Include current completed five-module and remote-files work, preserving original
  source changes and protective stash. Review staged source for secret files.
- Codex handles version, docs, source commit/tag and GitHub publication.
- All checks, builds and package verification go through OpenCode, main AND small
  model opencode/step-5-preview-free, user-authorized free fallback; dedicated task
  config only, never modify global tool settings.
- No business/UI changes, ADB, real SSH/Agent commands, billing settings, repository
  visibility changes, or existing Release/tag/asset overwrites.
- Release commit contains [skip ci]; do not invoke any workflow. Check actual
  Actions runs for the exact source SHA rather than assuming nothing ran.

## Build and acceptance

Use an isolated checkout of the exact release-source commit, not a dirty mixed
source tree. Preserve all old APK/AAB, backups, signing files and outputs. Space
cleanup may remove only explicit validated regenerable project intermediates;
never flutter clean or delete entire build directories, other projects or caches.
Record targets and regained space. Missing resources are not passed gates.

Android: original fixed release key, three ABI APKs plus AAB when feasible. Verify
versionName=1.0.3, base build number=4 and ABI versionCodes, actual app ID, signature
integrity and certificate SHA256 against the fixed public certificate. Never
print passwords/private keys or upload them. Regenerate release registrants via
pub; no dev integration_test plugin in release APK. No dependency upgrades.

Linux: release x64 complete bundle including executable, libflutter_linux_gtk.so,
libvalhalla_smb.so, data/icudtl.dat and assets; retain notices/licenses. Check ELF
architecture, dependencies, archive integrity and versioned BUILD-INFO. Package
tar.gz, not executable alone. Runtime/real-server acceptance remains separate.

All assets: current build outputs only, explicit filenames, BUILD-INFO records
Norns Interactive, exact source commit and UTC build time; SHA256 sidecars and
manifest. Verify local integrity and absence of signing files/private-key payload
before upload. Create new v1.0.3 draft, upload allowlisted verified assets, compare
GitHub uploaded names/sizes/digests to local values, then publish as latest.
Keep v1.0.0/v1.0.1/v1.0.2, their tags and assets intact.

Current implementation checks already completed: 2165 tests passed, 18 opt-in
integration checks skipped, zero failed; full analyze and diff check exit 0. After
the version-only change run current source/static/release gates, not a redundant
full suite unless builds expose a source problem. Final evidence must record real
exit codes and matching new artifacts; an interrupted process returning 0 is not
proof of success.

## Space preparation (Codex, no user data removed)

Recursive cache deletion was rejected by the terminal's safety check, so it was
not executed. Used the safer narrow approach: resolve concrete files, check
regular file/non-symlink, then unlink 20 explicit regenerable files only: 13
old app.dill kernels under the project's .dart_tool/flutter_build; one old
isolated app.dill; three merged libflutter.so intermediates and three Gradle
zip-cache files under /tmp/opencode/valhalla-v1.0.2-icon-source. Remaining cache
directories and all outputs, APK/AAB/backups/source/signing files stayed intact.
Space increased from 203MiB to approximately 1.9GiB. Cache files are not restored
from trash but are recreated by a future build; no business data was deleted.

Doctor reported some Android SDK licenses unaccepted; no license was accepted
automatically. That does not prove the installed components cannot build; attempt
the actual requested build before treating this as a blocker. Record the real
build result separately.
