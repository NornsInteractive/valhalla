## 二、OpenCode 基线测试实际验证情况（已通过）

OpenCode 针对当前用户代码实现完成了 7 项基线验证，**当前已全部通过**：
1. **预载 60 条消息**：初次加载定位正常通过。
2. **异步历史**：异步拉取会话历史后能够正确触底。
3. **会话切换**：正常切换会话后定位及重置正常。
4. **快速切换**：连续快速切换会话/目标未发生错乱。
5. **手动上滑新增输出**：用户手动离开底部浏览时，新增输出未出现异常强制拉回。
6. **透明度（Opacity）**：界面可见性正常，未发生永久隐藏（0.0 白屏）。
7. **200 行长回复**：超长内容展示与滚动定位通过。

### 当前进展与决策
- **断言收紧**：OpenCode 正在进一步收紧断言（验证最后一条消息的底部必须实际完全落在 Viewport 视口内）以及 390dp 宽屏测试。
- **方案决策**：**暂不采用单帧 jump 改写**。正向按需列表（`reverse: false`）的 `maxScrollExtent` 属于动态测量与累加估算，单帧强改跳跃存在估算未满、无法真正触底的新回归风险，维持当前已通过测试的实现机制。

## 三、静态推演风险与实际测试结果区分说明

下表明确区分静态理论分析关注点与 OpenCode 实际测试验证结果，**不把理论推演宣称为已复现缺陷**：

| 关注项 | 静态理论分析风险（推演） | OpenCode 基线实际测试结果（事实） |
| :--- | :--- | :--- |
| **1. `initialScrollOffset: 1000000`** | 正向按需列表在理论上从 index 0 向前测量，长历史存在首帧布局遍历耗时 | 60 条消息与 200 行长文本测试均正常渲染，未出现挂死或异常 |
| **2. Controller `dispose` 时机** | 在 build/listen 中 dispose 旧控制器理论上对挂载中的 ScrollPosition 存在解绑断言隐患 | 会话切换与快速切换测试均平稳执行，未触发框架级断言或崩溃 |
| **3. 空页面异步加载** | 空状态时未挂载列表，推演可能导致重试计数消耗后异步首批消息展示异常 | “异步历史”基线用例实测通过，消息加载后能够顺利就绪与展示 |
| **4. 多帧估算触底性** | 动态高度长文本在理论上逐帧扩展，固定 5 帧可能未达绝对物理底部 | 60 条及 200 行长内容基线测试均通过，OpenCode 正在针对视口完全可见收紧断言 |
| **5. 用户手动上滑保护** | 缺乏显式 `userScrollDirection != idle` 检查理论上可能打断用户浏览 | “手动上滑新增输出”测试用例实测通过，未破坏用户脱离底部的状态 |
| **6. 快速切换目标保护** | 异步微任务交错理论上存在闭包与跨会话竞争 | “快速切换”测试用例实测通过，目标过滤守卫在当前调度下有效 |
| **7. Opacity 永久隐藏** | 重试或异常退出分支若未触发 setState 理论上存在维持 0.0 白屏死锁可能 | “透明度”专项测试实测通过，透明度标记正常翻转，视图完全可见 |
