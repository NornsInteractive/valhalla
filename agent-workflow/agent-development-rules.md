# 通用 Agent 开发规则

## 1. 任务分流

- 业务任务：由主 Agent 负责需求、架构、状态、数据、服务、基础设施和非 UI 测试。
- UI 任务：由 Antigravity 负责页面、组件、布局、交互、主题、文案和 UI 专属测试。
- 混合任务：主 Agent 先定义可调用的状态和服务契约，再通过 UI handoff 交给 Antigravity。

不确定任务归属时，先拆分边界，不要让两个 Agent 同时修改同一文件。

## 2. 文件归属

### Antigravity 默认可修改

- `lib/features/**`
- `lib/widgets/**`
- `lib/l10n/*.arb` 及 UI 相关本地化资源
- UI 专属测试和 UI 资源

### 主 Agent 默认可修改

- `lib/core/**`
- `lib/data/**`
- `lib/infrastructure/**`
- 平台桥接、服务脚本、依赖和非 UI 测试

### 共享文件

`lib/app/**`、生成文件、路由入口和其他跨层文件必须在 handoff 中逐项列出；
未列出的共享文件不得修改。

## 3. 工作流

1. 阅读本目录规则、相关项目规则和当前实现状态。
2. 检查现有实现、调用方和未提交改动，先复用已有代码。
3. 将任务分流为业务、UI 或混合任务，并声明允许修改的文件。
4. 混合任务先完成业务契约，再创建 UI handoff。
5. Antigravity 按白名单实现 UI，不能顺手修改业务层或基础设施。
6. 发起 Agent 检查 `git diff --name-only`，确认没有越界文件。
7. 根据验收清单运行格式化、静态分析、相关测试和必要的真实环境验证。
8. 把已验证结果、未验证条件和后续缺口写入 handoff 或实现状态文档。

## 4. 交接要求

每份 UI handoff 至少包含：

- 目标和用户触发场景；
- 已有的 Provider、状态、方法和本地化键；
- 允许修改的文件白名单；
- 明确禁止修改的目录；
- 空态、加载态、错误态、窄屏和无障碍要求；
- 运行的命令及其结果；
- 尚未完成的真实设备或服务器验收。

## 5. 冲突和失败处理

- 发现越界修改时先停止合并，保留 diff 并退回 handoff，不用猜测意图修补。
- 共享文件发生冲突时由主 Agent 统一整合，Antigravity 不直接解决跨层冲突。
- 测试失败必须记录失败命令和原因；不能把未验证标记为已完成。
- 不得在 UI 层绕过 Provider 直接调用 SSH、ACP、数据库或平台服务。
