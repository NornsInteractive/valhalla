1. **Android APK attempt 1 — exit 1** (145.2s). Gradle failed while evaluating

   `libmpv-android-video-build` v1.1.7 `default-arm64-v8a.jar`. Transient network
   only; no source edit; retried unchanged → **exit 0**.
2. **Linux attempt 1 — exit 1**. CMake `download_and_verify` integrity check failed
   for `mimalloc-2.1.2.tar.gz` (transient network). Retried unchanged → progressed.
3. **Linux attempt 2 — exit 1**. CMake install tried to write the runner to
   `/usr/local/valhalla` (permission denied). Root cause: the task-owned
   `CMakeCache` recorded `CMAKE_INSTALL_PREFIX=/usr/local` during the aborted
   first configure inside `include(flutter/generated_plugins.cmake)` (line 75),
   before the default-prefix fallback at lines 81–84 ran, so the retry reused the
   stale prefix. Resolved **without** any SDK/template/source edit and without
   sudo or a `/usr/local` write, by reconfiguring only this task-owned build
   cache:
   `cmake -S …/linux -B …/build/linux/x64/release -DCMAKE_INSTALL_PREFIX:PATH=…/build/linux/x64/release/bundle`
   (log `/tmp/opencode/v104-linux-prefix-reconfigure.log`). Final
   `flutter build linux --release` then **exit 0**.
   Caveat on the exit status of that cmake invocation itself: the required
   command's outer helper shell terminated nonzero because the trailing quoting
   (`; exit ""`) was expanded by the shell, so no clean `cmake` exit code was
   captured. What is factually verified is that CMake reported
   "Configuring done / Generating done" and wrote the build files with the
   corrected prefix (the cache now reads
   `CMAKE_INSTALL_PREFIX:PATH=…/build/linux/x64/release/bundle`), and that the
   subsequent `flutter build linux --release` exited **0**. No build, source,
   network or environment change accompanied the correction.
